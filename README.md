# IIJmio 端末在庫監視 (GitHub Actions + Playwright)

IIJmio の端末ページ (POCO F7 Pro / POCO X8 Pro) を15分おきにヘッドレスブラウザで開き、在庫関連の表記が前回から変化したら Gmail 経由でメール通知します。

## 仕組み

1. GitHub Actions が定期実行され、Playwright (Chromium) でページを描画してテキストを取得します。
2. 「一時在庫切れ」「次回入荷未定」などの在庫切れ表記と、「お申し込み」などの購入可能表記の出現状況を集計します。
3. 前回の状態 (`state.json`、リポジトリにコミットして保存) と比較し、変化があればメールを送ります。在庫切れ表記が減った・購入可能表記が増えた場合は件名に「在庫復活の可能性」と付きます。
4. ページ取得に失敗した場合は前回の状態を維持し(誤通知防止)、ジョブを失敗させます。GitHub の標準機能により、ジョブ失敗時はリポジトリオーナーへ通知メールが届きます。

初回実行時は、基準となる現在の状態を記録し、セットアップ完了メールを送ります。このメールが届けば通知経路は正常です。

## セットアップ手順

### 1. Gmail のアプリパスワードを発行する

1. Google アカウントで2段階認証を有効にします (アプリパスワードの発行に必須です)。
2. https://myaccount.google.com/apppasswords を開き、アプリパスワードを新規作成します。
3. 表示された16桁のパスワードを控えます (スペースは除いて構いません)。

### 2. GitHub リポジトリを作る

1. GitHub で新しいリポジトリを作成します。**Public を推奨**します (理由は後述の「実行時間の上限」参照)。
2. このフォルダの中身をすべてプッシュします。

```bash
cd iijmio-stock-watch
git init
git add .
git commit -m "Initial commit"
git branch -M main
git remote add origin https://github.com/<ユーザー名>/<リポジトリ名>.git
git push -u origin main
```

### 3. Secrets を登録する

リポジトリの Settings → Secrets and variables → Actions → New repository secret から、以下を登録します。

| Secret 名 | 内容 |
|---|---|
| `GMAIL_ADDRESS` | 送信元 Gmail アドレス |
| `GMAIL_APP_PASSWORD` | 手順1で発行した16桁のアプリパスワード |
| `NOTIFY_TO` | 通知先アドレス (省略可。省略時は `GMAIL_ADDRESS` 宛に送信) |

### 4. 動作確認

1. リポジトリの Actions タブ → 「IIJmio stock check」→ 「Run workflow」で手動実行します。
2. 数分後、「セットアップ完了 (初回実行)」のメールが届けば成功です。
3. 以降は15分おきに自動実行され、変化があった時だけメールが届きます。

## カスタマイズ

- **監視対象の変更**: `check_stock.py` 冒頭の `TARGETS` に名前と URL を追記・削除してください。
- **チェック間隔**: `.github/workflows/check.yml` の `cron` を変更してください (例: `*/30 * * * *` で30分おき)。GitHub の仕様上、指定時刻から数分〜十数分遅れることがあります。
- **判定キーワード**: 初回実行メールの「該当箇所の抜粋」を見て、実際のページの表記に合わせて `OUT_MARKERS` / `IN_MARKERS` を調整すると精度が上がります。

## 注意事項

- **実行時間の上限**: Public リポジトリでは Actions の実行時間は無料・無制限です。Private リポジトリは無料枠が月2,000分のため、15分間隔 (1回あたり約2分 × 約2,900回/月) では超過します。Private にする場合は間隔を60分以上に広げてください。
- **通知の性質**: この仕組みが検知するのは「ページ上の在庫関連表記の変化」です。IIJmio の在庫は補充後に短時間で売り切れることがあるため、通知が届いたら早めにページを確認してください。
- 長期間 (60日) リポジトリに変更がないと、GitHub が定期実行を自動停止することがあります。停止時は Actions タブに再有効化のボタンが表示されます (`state.json` の更新コミットが入る限り、通常は停止しません)。
